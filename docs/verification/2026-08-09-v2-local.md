## Deterministic fault drills

| Drill | Status | Deterministic evidence |
|---|---|---|
| Redis unavailable | PASS | Adapter classifies connection failure; ordering returns retryable and creates no idempotency/order row; reconciliation still appends a `BLOCKED` report |
| Ambiguous/lost reply | PASS | Timeout is `AMBIGUOUS`; same-key acquire replay does not decrement again; ambiguous post-commit confirm attempts quarantine |
| Restart/state loss | PASS | Deleting current generation preserves completed MySQL replay while a new request fails closed before MySQL |
| Partial or unknown generation | PASS | Missing metadata and unknown script version return bounded not-ready/version decisions |
| Duplicate lifecycle | PASS | Confirm and both release paths are idempotent and capacity never exceeds initialization |
| MySQL rejection/unknown outcome | PASS | Proven rejection releases; unknown transaction outcome quarantines without unsafe compensation |
| Post-commit closure release failure | PASS | MySQL closes and restores inventory; Redis failure is recorded without undoing the commit |
| Drift and rebuild | PASS | Excess, missing, orphaned, terminal, missing-confirmation, proven non-effective, and unresolved fixtures preserve MySQL; unresolved work leaves the replacement unpublished |

These drills inject failures at deterministic adapter/state seams. They do not claim a production Redis topology, network partition test, persistence guarantee, or automated failover result.

## Scope and synchronization readiness

A source/dependency search found no RocketMQ, Kafka/AMQP, Outbox, Debezium/CDC, Redisson/distributed lock, or automatic fail-open implementation. Admission code reads MySQL stock only through the reconciliation snapshot; it does not maintain application-owned durable inventory. The only Redis client usage is contained in the admission adapter and the experiment evidence path.

The delta specs cover three modified capabilities (`synchronous-ordering`, `inventory-reservation`, and `concurrency-experiments`) plus the two new Redis capabilities. Implementation, tests, configuration, runbooks, metrics, and evidence map to those deltas. All five deltas were subsequently synchronized to main specs and the 46/46-task change was archived as `2026-08-09-add-redis-lua-admission-control`. Commit, push, and publication remain `NOT_RUN` and require separate authorization. RocketMQ transport, delayed messaging, consumer Inbox/retry/DLQ, Transactional Outbox, CDC comparison, automated refund execution, and production HA/capacity claims remain deferred.
